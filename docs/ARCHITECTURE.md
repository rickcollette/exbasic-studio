# Architecture

exBASIC Studio is a Wails 3 desktop application: a Go backend and a
Svelte 5 + CodeMirror 6 user interface in the platform web view. The
compiler, the emulator helper and the ATR tool are separate programs that
the backend starts as child processes.

## Frontend

- **One adapter.** UI code never imports the Wails runtime or the bindings.
  It calls `native()` from `lib/native.ts`. Production installs
  `native.wails.ts`; tests and browser-only runs install `mockNative.ts`, a
  deterministic in-memory backend.
- **Stores** are classes using Svelte runes (`*.svelte.ts`). `Workbench`
  creates them, wires their callbacks and owns cross-cutting workflows
  (open folder, build, run, go to definition) and the command table used by
  menus, the palette and the keyboard.
- **Editors.** Each tab owns a CodeMirror `EditorState`, so undo history is
  per tab. A tab is dirty exactly when its document differs from the last
  saved text. One `EditorView` shows the active tab; the split pane is a
  second view whose changes are mirrored in both directions.
- **Sprite Studio tabs** are not text documents. They share the tab strip
  through the editors store's `VirtualTabHost` (ids starting with `@`), which
  orders, persists, restores and saves them alongside text tabs; the sprites
  store owns their contents and undo history. The model, PMG codec and merge
  in `lib/sprites/` are pure functions, so they are tested without a browser.
- **Language support** is structural (highlighting, folding, outline,
  completion). The compiler stays the authority for diagnostics. The
  keyword catalog and parser tables are generated by
  `frontend/scripts/gen-language.mjs` from the compiler's `.syn` files and
  Appendix A of the manual, and CI fails when they drift.

## Backend

- **Facade.** `StudioService` holds the active project and delegates. Its
  methods are the public API of the backend; each validates its arguments.
- **Operations.** Builds, runs and Git network commands run through
  `operations.Manager`: a context for cancellation, an ID, streamed output
  and exactly one completion event. Events carry a per-operation sequence
  number; the UI applies them in order and ignores duplicates.
- **Terminal.** Sessions are real shells on a pseudo-terminal. On Windows
  the shell runs in a job object so closing a terminal ends its children.
- **State** lives in the user configuration directory, never in the
  project: `state.json` (versioned), `recovery/`, `logs/` and the emulator
  profiles. A damaged or newer state file is set aside, not overwritten.

## Build pipeline

`compiler.Build` runs the compiler with an argument vector, streams its
output and returns a structured result: argv, artifacts, diagnostics,
duration and the metadata location.

With the bundled compiler it passes `--metadata-json`, and the compiler
writes a versioned document (on success and on failure) containing source
hashes, structured diagnostics, line-to-address mappings and typed symbols.
A compiler without that capability still builds; diagnostics are then read
from its text output, and source debugging is disabled with an explanation.

## Debugger

exBASIC programs mix interpreted bytecode and native 6502 code. The
metadata gives, for every executable source line, the address ranges of its
code and whether they are bytecode or native.

The helper is built with Atari800's code-breakpoint support. While
something can stop the machine, the CPU core calls the helper after every
instruction. The helper computes the *code location*: the bytecode pointer
when the program counter is at the interpreter's dispatch address, the
program counter otherwise. Breakpoints and line starts are tables indexed
by that location, so bytecode and native lines are handled the same way.

Stepping is implemented in the helper (instruction, line, over `JSR`, out
via the return stack, run until). The Go side maps locations to source
lines, relocates breakpoints, disassembles, walks the stack and decodes
watches. A build whose source hashes no longer match the files on disk is
refused.

The helper protocol is newline-delimited JSON with a version handshake;
requests and responses are bounded in size on both sides. The helper stays a
separate GPL process.

## Invariants

- One workspace at a time; workspace paths are relative and validated.
- No shell interpolation for any child process.
- Nothing from an untrusted workspace is executed.
- Application state never enters a project directory.
- The frontend reaches the backend only through the adapter.
- Generated files (bindings, language catalog) are checked in and verified
  by CI.
